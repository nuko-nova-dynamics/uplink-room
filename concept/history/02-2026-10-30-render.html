What every agent gets

  • A name and avatar, always labeled as an agent
  • A person who owns it and answers for it
  • Access only to the channels, projects, and tools it's given
  • A spending limit
  • A visible state: working, waiting on you, done, or stopped
  • A log of every action and who asked for it
  • A stop button anyone in the channel can press
  • Its own token, revocable in one click

Who else is building this

The idea of people and agents sharing one workspace is taking off. As of October 2026:

Slack
Dreamforce 2026: code channels where the team watches an agent work, steers it, and ships a preview. Surfaces are live interfaces pinned to a channel. Agents from Anthropic, Cognition, GitHub, Vercel, and OpenAI.
Claude Tag
June 2026, Slack only, beta for Team and Enterprise. One Claude per channel that everyone shares, with admin-set tools, spending limits, and a log of who asked for what.
Grok Bot
August 2026, beta. Always-on agents with their own cloud computer, messaged like coworkers and placed in group chats. A closed app.
Amp
Multiplayer threads: teammates prompt the same coding agent for 7 days, billed to the owner. A Space adds voice, video, and screen share to a thread.
Buzz (Block)
Open-source developer preview. Chat with teammates and agents, then plan, code, and open PRs in the same place.
Ando
Raised $20M (TechCrunch, Sep 2026). Messaging where agents have their own identities and can follow calls.

Where Malecón is different

None of the products above combine agent-operated computers, live terminals, shared browsers, and Discord-style voice in one place that any vendor's agent can join. Each vendor pushes its own agent; Malecón stays neutral. That combination is the opening, not any single feature.

Risks

  • Slack already ships code channels, and Buzz is free and open source.
  • Agents with computers and saved logins are a security target. Each needs tight, revocable access.
  • Computer use still fails on about half of long tasks.
  • Agent compute and model costs grow with use, which makes per-seat pricing hard.

Verdict: worth building now as the team's own tool. If it becomes a product, start with a narrow group, such as small game or software studios that already run many agents.

Build order

Each step is usable on its own before the next one starts.

  1. ChatElectron app, Clerk sign-in, channels, threads, DMs, and file uploads on Convex.
  2. CallsVoice channels, video, and screen share with sound on LiveKit.
  3. Agent threads and terminalsOne Linux computer, Claude Code and Codex runners, the driver and suggestion flow.
  4. ComputersComputer use with live view, take control, pause, and fork, on Linux first.
  5. ProjectsThe board of runs, the waiting-on-you inbox, attempts, and spending limits.
  6. Open the doorsThe agent gateway (MCP and A2A) for OpenClaw, Hermes, Grok, and others, plus ACP agents.
  7. Files, apps, and browsersPDFs, docs, canvases, HTML apps in messages, and shared browsers.
