# Agents and runs message each other through the room, and the receiving agent decides what to do

Julio wants every agent the team uses to message every other while they work: his Claude Code run and a teammate's Claude Code or Codex run on another machine, a run and an A2A agent such as Icarus, and the hosted assistants (ADR 0028). No product does this across two people's accounts: Claude Code's cross-session messaging, Codex subagents, Muse Code's session messaging and T3 Code's thread tools all stop at one person's account (`research/agent-messaging/harness-surfaces.md`). Open-source relays (Concord MCP, hcom, MCP Agent Mail) let any agent claim any sender name, and have no accounts, private channels or audit record (`research/agent-messaging/concord-and-hcom.md`, `agent-mail-peers-and-others.md`). The room already has the people, the accountability and the places, so it carries the messages. Julio decided this on 2026-11-05 in a grilling session.

## Decisions

- **A live run is addressable as itself.** It is mentioned and posts under a name made of its harness and driver, such as Claude Code (Julio), with its task shown beside the name and a number when one person has two live runs of the same harness. Its driver at the time answers for what it says. It is not a new agent member: Claude Code and Codex stay harnesses. The run is the smallest address; subagents and teammates inside it are the harness's business.
- **Messages are ordinary chat messages** in the places that exist (a project's channel, replies, a direct message), visible to people, under the access rules of ADR 0015 and ADR 0016. A live run can be a member of a direct message.
- **A run hears what an A2A agent hears** (ADR 0024): mentions at a channel's top level, mentions and its own thread in replies, everything in a direct message, plus replies under a message the run posted.
- **Anyone who can see a run can message it**, person or agent. Its driver can narrow that to themselves and their own agents, as an A2A agent's person can (ADR 0012). Amended by ADR 0039: a message from a direct message or private channel reaches a run only when everyone who can see the run's output is a member there. Amended by ADR 0044: a run that joined with `uplink join` starts closed, seen and heard only by its person and their agents, until its person opens it.
- **A message can carry an instruction, and the receiving agent decides whether to follow it.** Julio's example: telling the agent working on a 3D model to release it because he's taking over. Each message a run receives is labelled with the sending run or agent, the person accountable for it, and whether that person is this run's driver. Mailopoly Switchboard and Claude Code's own messaging make messages information only; we chose otherwise. Approvals stay out of chat: only the driver, the task's owner or an admin answers one, or an agent through the approvals function with its scope (ADR 0005).
- **No loop limit between agents.** Julio's reasoning: current models can tell when a conversation is done. This replaces ADR 0024's "the room never sends one agent's answer to another agent".
- **Messages land mid-task wherever the harness allows, otherwise at its next turn.** The bridge delivers each one, adding it to the turn without stopping it: Claude Code through a `PostToolUse` hook returning `additionalContext` (`asyncRewake` when idle), Codex through the app server's `turn/steer` (`codex queue --resume` when idle), a T3 Code thread through `message.dispatch` with `steer_active`, Hermes Agent through its `steer` mode, and Grok Build between turns over ACP. The app shows each run as hearing you mid-task or between turns. For thread messages from other runs, this replaces ADR 0023's choice to queue behind the turn. Amended by ADR 0037: a T3 Code thread is steered only where T3 Code says steering stops no running tool (Codex today); other threads hear between turns. Amended by ADR 0040: Hermes Agent v0.23.0 runs its sessions on the profile's gateway, so the bridge steers a Hermes terminal's session there (`session.steer`) and submits to it when idle.
- **A run on a bridge machine posts with `uplink-bridge say` and `uplink-bridge reply`.** The bridge, already on each terminal's PATH for Claude Code's hooks, knows which terminal or thread called and posts as that run, so the agent never holds a key.

## Consequences

- Experiments before building on each path: whether the bridge can tell which T3 Code thread called `uplink-bridge` (if not, thread runs get a short-lived key); `turn/steer` against a person's interactive `codex`; Hermes's `steer` mode for `hermes` in a terminal; Muse Code's `PostToolBatch` hook, whose output format isn't published.
- A plain shell has no delivery path; its agent reads the room with the `uplink` command-line tool.
- With no loop limit, a runaway exchange costs the subscriptions of the people involved until someone stops it. The run's driver can stop the run or narrow who may message it.
- File claims and a shared task list, which Concord, Agent Mail and Claude Code's teammates have, are out of scope for now.
