# Outside agents get work over A2A, act through the Room API, and one reporter keeps each run's state

Agents such as Hermes and OpenClaw run on their own gateways. The room sends them work there over A2A (the Agent2Agent protocol, version 1.0): mentioning one in a channel, or starting a run with one on a task, becomes an A2A message, and usually an A2A task. Everything the agent then does in the room (posting, reading tasks, answering approvals) goes through the Room API with its agent key, its scopes and its approvals, as for every other agent (ADR 0003). The agent runs on its own gateway, so ADR 0001 still holds. The room keeps no A2A server of its own: other agents can't call into the room over A2A yet. Julio decided this on 2026-11-02 in #8, from `research/decision-a2a-agents.md`.

We chose both protocols over the Room API alone, because a tool connection doesn't let the room hand an agent work or see it progress, and over A2A alone, because A2A has no channels, members, scopes or approvals.

## One run, one reporter

An A2A task is the agent's execution; it is not the glossary's Task. One A2A task is bound to one room run. The agent owns the execution. A worker in the backend is the run's only reporter. The backend owns the stored run state, the driver, Inbox routing, permissions and the activity log. No Room API function reports an A2A run's state, so an agent's MCP or HTTP calls can't overwrite it. `runs.stop` asks the agent to cancel, and the run shows Stopped only after the agent reports its task Canceled.

| A2A task state | Run state |
| --- | --- |
| Submitted, Working | Working |
| Input required | Waiting, with the agent's question, in the driver's Needs you. `runs.reply` answers on the same task |
| Auth required | Waiting: someone must sign in at the agent's gateway. The room never handles that sign-in |
| Completed | Done, with the answer and up to 8 artifacts kept |
| Failed, Rejected | Failed, with the reason ("Rejected: …" for a rejection) |
| Canceled | Stopped |
| Unspecified, contact lost, task gone at the agent, delivery not confirmed, no longer followed | Unknown, with the reason and the last state the room saw |

A direct Message reply, with no task, finishes the run as Done. A finished A2A task can't restart, so more work after it is a new run. That new run continues the same conversation, in the agent's same A2A context (ADR 0024).

## Consequences

- The worker runs in Convex actions in the Node.js runtime, never in a mutation. Mutations record what someone asked for and schedule a step. A step spends at most 8 minutes on calls, inside Convex's 10-minute action limit. Each step holds a lease on its run's binding, so steps never overlap, and it rechecks that the agent, the person accountable for it and the endpoint are still there before it calls out. It commits only bounded observations: texts cut to 4,000 characters, at most 8 artifacts with 4 http(s) links each, and responses read with a size limit.
- A reply or a stop takes effect within a few seconds. A step holding a stream checks every 2 seconds whether someone asked for one, and ends the stream if so.
- The worker follows a task over SSE (`SubscribeToTask`, in windows of up to 4 minutes, since an action runs for at most 10) when the Agent Card offers streaming, and polls `GetTask` otherwise, from every 2 seconds up to once a minute. A subscription that closes without news is retried on the polling schedule, not at once. Every response body has a deadline. After 4 failed contacts in a row the run shows Unknown. It stops following after a day without contact, or a week without change. A cron restarts steps that died.
- An agent's endpoint is registered by the person accountable for the agent, or by an admin (an admin agent also needs `team.admin`). The room reads the Agent Card from `/.well-known/agent-card.json` and sends requests only to that origin: the card's JSON-RPC interface must be on it, and redirects are never followed. Addresses must be public https. `A2A_ALLOW_INSECURE_PEERS=1` on a deployment also allows http and private addresses, for development. The deployment's own `*.convex.cloud` and `*.convex.site` hosts are refused always. A gateway on a laptop or a tailnet needs a public https address (a tunnel, Tailscale Funnel) until a bridge can carry A2A.
- Convex's default runtime offers only `fetch`, which gives no say over DNS or the address it connects to. So every A2A request goes through `node:https` with a `lookup` hook (`lib/a2a/guardedFetch.ts`). Each request resolves the host again, on a fresh connection, and refuses it when any answer is blocked. Blocked means loopback, private, link-local, carrier-grade NAT, cloud metadata (169.254.169.254, fd00:ec2::254, 100.100.100.200, 168.63.129.16), documentation, multicast or reserved, including IPv4 inside IPv6 (mapped, compatible, NAT64, 6to4). The address checked is the one the socket connects to, so a name that rebinds after registration is refused at its next use. TLS still checks the certificate against the name. What remains: an address that is public on paper but internal to Convex's own network isn't on the list.
- Changing an endpoint's address to another origin deletes its token. Tokens are also sealed to their endpoint and origin, and the worker sends one only to the origin it was given for. Each endpoint has a generation that moves on with any change of address or interface. A run follows only the generation it started on; after a change, the room stops following it (Unknown), so a task id from one gateway is never polled or canceled at another.
- The token the room sends a gateway is not an agent key: an agent key lets the agent act in the room, while this token lets the room send the agent work. It is kept in its own table, sealed with AES-GCM under `A2A_CREDENTIALS_KEY` and bound to its endpoint. Only a worker step opens it, just before a call, and the mutation that saves what the agent reported, to take the token out of it once streamed pieces are joined (ADR 0018). No query, Room API answer or activity row carries it; the app shows its last four characters. The room supports a bearer token or a token in a named header. OAuth, OpenID Connect and mutual TLS are not supported yet.
- A2A cards don't say whether `CancelTask` or `ListTasks` work, so the room learns it by trying. OpenClaw supports neither. When an agent can't cancel, the room says so and offers to stop following the run (`runs.detach`), which shows it Unknown ("the agent may still be running"), never Stopped.
- Every message keeps its message id and is never sent twice. When delivery is unclear (a lost connection, a timeout, an HTTP 5xx or a JSON-RPC internal error), the room looks for the message id in the agent's tasks before anything else: up to 5 pages of `ListTasks` with artifacts, one page per step with its place saved between steps, reading a finished task whole when a listing leaves its artifacts out (the task found is saved first, so a failed read is retried on its own and the search isn't run again), or `GetTask` for a reply. If the agent can't list tasks, the run shows Unknown: delivery not confirmed.
- Anyone in the team can send an agent work, unless its person sets it to take work only from them. An agent that mentions another needs the `runs.start` scope for the mention to start a run, and an agent can't send work to itself. The worker never posts in a channel on the agent's behalf: an answer shows on the run, and the agent posts with its own key if it wants to. Amended by ADR 0024: in a conversation (a channel, thread or direct message where the agent was called) the room posts the agent's answers, questions and progress there as the agent's messages, and a reply after a task finished continues the agent's context as a new run.
- The room speaks A2A 1.0 over JSON-RPC (`SendMessage`, `SendStreamingMessage`, `GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`, with `A2A-Version: 1.0`). Hermes and OpenClaw both serve it. Amended by ADR 0018: an agent whose card names A2A 0.3, or that answers only 0.3's methods, is spoken to in 0.3. Cards that offer only gRPC or HTTP+JSON, or A2A 0.2 and earlier, are refused with a message saying so. Push notifications would need an address the agent calls back, so they wait with the inbound A2A server.
- OpenClaw keeps a task Working while a local approval waits at its gateway. The room can only show Working there; a true Waiting would need an adapter for OpenClaw's own events.
- Tests run the room's client against a local agent built on the official SDK (`@a2a-js/sdk`), configured to act like Hermes (streaming, cancel, task listing, a per-peer token) and like OpenClaw (none of those). The same agent behind a tunnel was used for an end-to-end check against the dev deployment. The first real gateway, a Hermes A2A gateway (Icarus, 2026-11-04), read the room's chunked request bodies as empty and answered "method not found"; requests now carry `Content-Length`, and the test agents read bodies the way Hermes does (ADR 0018).
